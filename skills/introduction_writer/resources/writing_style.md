# 教材寫作規範（Writing Style Guide）

本文件定義本專案所有教材的寫作規範。
所有教材、講義、章節內容與課程文件，除非使用者另有要求，均應遵循本規範。
本文件的目的不是限制寫作自由，而是確保不同章節、不同課程以及不同作者所撰寫的教材，能夠維持一致的閱讀體驗與專業品質。

---

# 一、整體寫作風格

所有教材應採用平實、親切、簡單明瞭、不過份輕浮的語氣表達，
並以「大學教材」或「專業專書」作為寫作目標。
但避免聊天式回答、口語化表達、投影片式排版，以及社群媒體文章常見的寫作方式。
教材應讓學生具有閱讀一本書，而不是閱讀 PowerPoint 或 ChatGPT 對話紀錄的感受。
因此，每一個概念都應完整說明，而不是僅提供結論。

---

# 二、段落組織

每一個段落應圍繞一個主要概念。
段落內應先介紹概念，再進一步說明原因、背景或應用，最後自然銜接下一段。
請避免：
- 一句形成一個段落
- 一個概念被切割成許多短句
- 每一句都換行
- 過多留白
如果一個概念需要較長的說明，應維持在同一個段落中，而不是拆成數個零碎的小段。

---

# 三、章節安排

教材應具有清楚的階層。
建議使用：

```text
# 章
## 節
### 小節
```

不要直接跳過標題層級。
例如：
```text
#
###
```
屬於不建議的寫法。

若沒有足夠內容，不必建立新的小節。
---

# 四、概念介紹方式

介紹新的知識時，建議採用下列順序：

1. 問題或背景
2. 概念定義
3. 運作原理
4. 實際案例
5. 與其他概念的比較
6. 小結

不要一開始便直接給出定義。
應先建立學生理解問題的情境，再介紹概念。

---

# 五、專有名詞

重要專有名詞第一次出現時，請同時提供中文與英文名稱及簡稱。

例如：

> 上下文工程（Context Engineering）

> 檢索增強生成（Retrieval-Augmented Generation，RAG）

之後即可直接使用中文或英文簡稱其中之一。

整份教材應保持一致。

不要同時混用：

- 長期記憶
- Long Memory
- Persistent Memory

除非刻意比較不同名詞。

---

# 六、程式碼說明

教材中的程式碼，不應直接貼上。

每一段程式碼之前，都應說明：

- 為什麼需要這段程式？
- 它解決什麼問題？

程式碼之後，再解釋：

- 哪些部分最重要？
- 哪些地方值得注意？

不要假設讀者能夠自行理解程式。

---

# 七、圖片與流程圖

若教材包含圖片、流程圖或架構圖，不應直接引用圖片。

應先介紹：

- 為什麼需要這張圖？
- 希望讀者觀察什麼？

圖片之後，再說明：

- 圖中各元件代表什麼？
- 圖片如何對應本章內容？

避免：

> 如下圖。

而應寫成：

> 圖 3-1 展示了 Context Engineering 的主要架構。從圖中可以觀察到……

所有的流程圖或架構圖都以`mermaid`語法呈現，而不是用簡單的ASCII文字畫出。

---

# 八、表格

表格的用途是整理資訊，而不是取代說明。

建立表格之前，應先介紹：

- 為什麼需要比較？
- 比較哪些面向？

表格之後，再整理：

- 最重要的差異
- 使用情境
- 應如何理解比較結果

不要讓表格孤立存在。

---

# 九、條列式內容

教材應以完整段落為主。

只有符合下列情況時，才建議使用條列：

- 流程步驟
- 比較項目
- 重點整理
- API 參數
- 檢查清單

不要把整個章節寫成大量條列。

若同一頁有超過三分之一內容都是條列，通常代表文字說明不足。

---

# 十、Markdown 使用原則

教材使用 Markdown 撰寫。

請遵循：

- 使用標準 Heading。
- 使用標準 Code Block。
- 適度使用 Table。
- 保持空白行一致。

不要：

- 混用 HTML。
- 使用過多 Emoji。
- 使用特殊 Markdown Hack。

教材應保持良好的可讀性。

---

# 十一、敘事連續性

章節之間應具有自然的轉承。
不要讓每一節看起來像獨立文章。

例如：

> 前一節介紹了 Context Sources，本節將進一步討論 Context 如何進入模型。

這類過渡文字能協助學生建立整體架構。

---

# 十二、教材深度

教材不應只有「是什麼」。

每一個重要概念，都應回答下列問題：

- 為什麼需要？
- 如何運作？
- 有哪些限制？
- 與其他方法有何不同？
- 實際如何應用？

如果只介紹定義，而沒有背景或應用，通常代表說明仍然不足。

---

# 十三、案例使用

每一章至少應包含一個案例。

案例可以來自：

- Antigravity 2.0 Desktop
- MCP
- AI Agent
- Python
- 課程專案
- 真實工作流程

案例應具有連續性。

不要每個章節都重新建立完全不同的情境。

---

# 十四、結語

每一章最後，都應加入一段簡短的小結。

小結不是重複內容，而是協助學生建立整體觀念。

建議回答：

- 本章最重要的觀念是什麼？
- 與上一章有何關係？
- 下一章將介紹什麼？

讓整本教材具有一致且流暢的閱讀體驗。

---

# 最終目標

完成教材後，請再次確認：

- 是否像一本教材，而不是 ChatGPT 回答。
- 是否以完整段落進行說明。
- 是否具有自然的章節銜接。
- 是否維持正式書面語。
- 是否兼顧概念、原理與案例。
- 是否具有一致的 Markdown 格式。

如果讀者能夠連續閱讀整個章節，而不覺得內容像一連串零碎回答，便符合本教材的寫作目標。
