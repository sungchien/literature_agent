# 教材撰寫 Skill

## Skill 目的

本 Skill 用於協助 AI Agent 將現有的 Markdown 文件或Power Pointer檔案，整理成具有完整結構的大學教材，在學期的第一週向學生介紹這個課程的內容、範圍與特色。

目標使用者為第一次接觸該課程的大學生，通常是不具程式設計基礎的人文社會學科大學生。

本 Skill 的重點並不是摘要內容，而是重新組織知識，使其成為具有良好教學流程、容易閱讀且適合作為課程教材的文件。

---

# 什麼情況應該使用本 Skill？

當使用者提出下列需求時，應優先使用本 Skill：

- 將原本的power pointer投影片改寫成有利於學生閱讀的Markdown文件
- 撰寫教材
- 整理課程講義
- 改寫 Markdown 文件
- 擴充教學內容
- 將筆記整理成教材
- 建立課程模組
- 編寫訓練教材
- 統一教材格式
- 建立教學文件

下列情況通常不需要使用本 Skill：

- 一般聊天
- 簡短問答
- 電子郵件撰寫
- 程式除錯
- 數學計算
- 圖片生成

# 工作流程

當 Agent 選擇本 Skill 後，請依照下列流程完成工作。

## 第一步：理解教材需求

先分析資料夾下其餘各週次的教材內容，包括：

- 教材主題
- 課程目標
- 課程要求，如作業或考試

若資訊不足，可先向使用者詢問。

---

## 第二步：閱讀教材寫作規範

開始撰寫之前，請先閱讀：

@Resource(resources/writing_style.md)

此文件定義教材的：

- 敘事風格
- 標題規則
- 段落安排
- 名詞使用方式
- Markdown 排版原則

除非使用者明確要求，否則所有教材均應遵循此文件。

---

## 第三步：閱讀教材範例

接著閱讀：

@Resource(examples/01_ai_introduction.md)

請觀察：

- 章節安排
- 段落長度
- 概念銜接方式
- 程式碼說明方式
- 表格與圖例呈現方式

請學習整體風格，而不是直接複製內容。

---

## 第四步：整理 Markdown

若來源文件為 Markdown，請先執行：

@Script(scripts/clean_markdown.py)

利用 Script 完成：

- Markdown 正規化
- 清除多餘空白
- 修正標題格式
- 統一換行
- 基本排版整理

完成後，再開始教材撰寫。

---

## 第五步：完成教材

依照前述規範，重新整理教材內容。

請特別注意：

- 建立完整章節
- 補充必要說明
- 保持敘事連續
- 使用正式書面語
- 維持教材閱讀體驗

避免：

- 投影片式排版
- 大量條列
- 一句一段
- 聊天式回答
- 社群媒體風格

**特別要求**：每節結束前都提供一個課堂上的小活動，
並且也有一段 ```老師的提醒``` 或 ```老師的真心話```，提醒容易混淆的觀念或實務上容易發生錯誤的地方。

# 輸出要求

完成教材時，請確認符合下列要求。

## 教材風格

採用正式書面語，但親切而平實，用簡單明瞭的方式說明，讓非電腦相關科系的大學生能夠理解。

閱讀體驗應接近大學教材

而不是：

- ChatGPT 回答
- PowerPoint
- 部落格文章

---

## 標題層級

使用標準 Markdown：

```text
# 第一層標題

## 第二層標題

### 第三層標題
```

請勿跳階使用標題。

---

## 段落原則

每一個段落應完整說明一個概念。

段落之間應具有自然轉承。

避免：

- 一句一段
- 過多留白
- 只有一兩行文字
- 大量碎片化條列

---

## 專有名詞

重要術語第一次出現時，請同時提供中英文名稱。

例如：

> Context Engineering（上下文工程）

之後即可直接使用中文。

---

## 程式碼

若教材包含程式碼：

- 程式碼前先說明目的。
- 程式碼後說明重要內容。
- 不要只貼程式碼而沒有解釋。

---

## 表格

表格用於整理資訊。

不要用表格取代完整說明。

表格前後均應搭配完整文字。

---

# 完成前檢查

送出教材之前，請再次確認：

- 是否符合教材寫作風格。
- 是否具有完整章節。
- 是否維持自然敘事。
- 是否遵循教材寫作規範。
- 是否參考教材範例。
- 是否完成 Markdown 整理。
- 是否沒有聊天式語氣。
- 是否適合作為正式教材。
- 每節結束前是否有課堂小活動以及```老師的提醒```。

---

# 最終輸出

請輸出完整 Markdown 文件。

除非使用者另有要求，不需加入任何額外說明。
